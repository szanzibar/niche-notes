# niche-notes — v1 spec

## Problem

Amplenote is a paid subscription, its sync has lost data, and it is cluttered. We want a scratch pad for a family of two or three: pop open a phone, jot a note or a list, find it later, and edit the same shopping list together.

## What v1 does

- **Notes in a tree.** Any note can hold notes. There are no folders and no notebooks. New notes go on top, made with the + in the tree's header or, outside a browser tab, with Ctrl or ⌘ and N. Every row has a + for a note inside it. Drag a note onto the middle of another to nest it, onto its top or bottom edge to sit next to it, or onto the header to bring it back to the top. A line shows where it will land, indented the way it will be. On a touch screen every row has a grip on its left that drags once a finger holds it, like the lines in a note. With a keyboard, Shift and a click pick every row from the last one clicked to that one, and Ctrl or ⌘ and a click pick or drop a single row. Picked rows wear the accent, and dragging one of them moves them all, in the order they were in, each with the notes under it. A plain click opens its note and lets the rest go. A folded row stays folded on every device of yours. However a note opens, from search, a link, Recent, Due or an alert, the tree beside it unfolds the notes above it that hide it and scrolls to its row, and they stay unfolded as if clicked. On a phone the tree shows with no note open, so there the last note opened on that device wears the open note's highlight, and the tree scrolls to its row on coming back from the note and on clearing the search, and at no other time. Back from a note returns to the tree, even when a widget, a calendar event or an alert opened the note, and back again leaves the app. A clock in the tree's footer opens a Recent section above it with the notes last opened on that device, the last one first and without the open note, so the note before is one tap away. It stays open or closed per device.
- **Pins.** A pinned note sits above its siblings, at the top level or inside its parent. Pins are ordered among themselves by dragging, and a drop never pins or unpins a note. A new pin goes below the other pins, and an unpinned note goes on top of the rest. A folded note still shows its pinned notes, so the ones seldom needed fold away under it.
- **Search.** The box at the top of the tree filters as you type, title matches first, then text, each with the words around the hit. A result with notes under it has a chevron that unfolds them, one level at a time, apart from how the tree is folded. While it has text, a filter button beside it opens Include trash and Include checked tasks. The trash counts and checked tasks don't, until the person changes that, and the choice follows them to every device. Trashed notes are marked. The open note, or on a phone with no note open the last one opened, is highlighted like its row in the tree. Arrow keys and Enter open a result on a keyboard, and the arrows go on from the open note. Ctrl or ⌘ and K put the cursor in the box from anywhere, showing the tree first where a narrow window hides it under a note. It works offline, since every note is on the device. The box always shows a clear button while it has text.
- **One editor.** A title field and a body with three heading levels, code blocks, quotes, dividers, bold, italic, strikethrough, inline code, links, highlight, bullet lists, numbered lists, task lists and tables. Two lists of one kind that touch are one list, so only a blank line keeps them apart. A checked task is crossed out. A task with tasks directly under it ends with how many of them are checked, like 2/5, hidden ones included. Ctrl or ⌘ and Enter tick the task at the cursor. Ticking a box never moves the note: while typing, the cursor goes to the end of that line, and otherwise the keyboard stays down. In a note set to hide them, it hides once it and every task under it are checked, for everyone and in its widgets. Checked tasks wait until the note has been still for five seconds, then fold away together, so ticking down a list never moves the next box. A note set to delete them hides them the same way and deletes them the next time it opens. The note's menu sets what checked tasks do, as one choice of Show, Hide or Delete, and has Uncheck all and Delete checked. Every box a button opens floats beside that button, over the note. Uncheck all clears every box, so a packing list can be used again. Delete checked removes the tasks that would hide, showing them for a moment first when they are hidden. Typing on a task offers, in a box under the line, up to five tasks that have been checked twice or more in the note, counting the ones Delete checked removed, that have a word starting with what the line says, most recently deleted first. Tasks still to do in the note aren't offered. A tap, or the arrows and Enter, makes the line that task, and Tab takes the one the arrows chose or else the first. Enter alone still starts a new line. Escape closes the box until the line's text changes, so Tab indents again. Everyone who can edit the note gets the same ones, offline too. A tap on a link puts the cursor in it, and its address in a box under it opens it, in place when it links to one of the app's notes. Every list line has a grip in the margin, shown for the line under the pointer, and on a touch screen for the lines the selection is on, since a hidden grip still works. Dragging the grip moves the line with everything nested under it. Alt+Shift and an arrow move the line at the cursor the same way, past the line above or below it. A finger holds the grip a moment first, so one that moves at once scrolls the note, and a tap on a task's grip, or between its box and its text, ticks it. Like a note in the tree, it lands above the line it is dropped on from the top of that line, below it from the bottom, and as its first child from the middle. The drag looks like one in the tree: the line rides as a box with its text, a row above a finger, its place stays dimmed, the line it goes into is outlined, and a line shows where it will land, indented the way it will be. A line dropped into another kind of list takes that list's kind. Headings and paragraphs drag by a handle that shows beside them. A list line with lines nested under it has a chevron left of its grip that folds them away and back, shown for the line under the pointer, and always on a touch screen and on a folded line. On a touch screen its tap area fills the margin from the line's left edge to the grip's dots, with the chevron in the middle. A fold is that person's own and follows them to every device, and Enter at the end of a folded line starts a line below what it hides. A heading folds the same way, hiding everything down to the next heading of its level or higher except the blank lines at the end of its section, which keep it apart from the next, and dragging a folded heading takes what it hides along. Enter at the end of a folded heading unfolds it, since a line under a heading belongs to what it hides. Ctrl or ⌘ with Shift and [ folds the line or heading at the cursor, or the one it sits under, and ] unfolds it. A tap toolbar does all of this on every platform, and markdown shortcuts work too (`- `, `1. `, `[] `, `# `, `> `, `---`). Opening a note puts the cursor in it: an empty title first, otherwise where this device last left the cursor, or the end of the text. A widget opens its note with the keyboard up, whether the app was running or closed. Enter or Tab moves from the title into the body. A new line or task made with Enter starts plain, without the bold, highlight or other marks at the end of the line before, while Shift+Enter stays on the line and keeps them. Undo history stays with the note while the app is open. Find in note, in the note's menu or Ctrl or ⌘ and F on a keyboard, marks every match in the note and steps through them, skipping hidden tasks and folded lines and headings. Holding Ctrl or ⌘ for half a second, with no other key, shows each shortcut beside its button, and a box over the toolbar lists the ones with no button. It hides when the key comes up or the window loses focus, and never shows without a mouse or trackpad or in the Android app.
- **Tables.** The toolbar's table button adds one with a header row, and while the cursor is in a table its tools sit beside that button: add a row, add a column, delete a row, a column or the table, each at the cursor. Return moves to the next cell, so a phone keyboard fills a row, and Return in the last cell adds a row. Return in an empty last row removes it and leaves the table, the way it leaves a list. Cells hold plain text, and a table wider than the note scrolls sideways. A widget shows each row as one line.
- **Dates and alerts.** A task can have a date, a time and a repeat. The date button in the toolbar sets them in a box that stays open until a tap elsewhere, and so does a tap on the date at the end of the line. Today, Tomorrow and Next week are one tap, and a line with a time can last 15 minutes to 3 hours in the calendar. A line that gets a time lasts as long as the last length the person picked, on any device, and half an hour until they pick one. A date can be typed into the line too, in English: today, tomorrow, next week, a weekday, a day like nov 20, a time like at 5pm or 17:00, and every day, every weekday, every other monday, every week, month or year, and every month on the first or on the last friday. The words wear the accent color while the cursor stays on the line, and the line's date shows what they make, with an ✕. Leaving the line, the note or the app turns them into the line's date and takes them out of the text. A tap on that date or Escape keeps them as words, and afterwards Undo brings them back. Typed onto a line that has a date, they change only what they say. Only words just typed count, so a line that already says Sunday roast stays as it is, and so does a line that is nothing but a date. A line repeats every week on chosen weekdays (all seven is every day), every month on a day of the month or on the 1st to 4th or last of chosen weekdays, or every year, each every one or more weeks, months or years apart, and the box says the rule in words. Daily in the box sets all seven in one tap, and Weekly after it starts with all seven ticked. The box shows the weekday beside the date, and its weekdays start on Monday. Dates and times follow the device's language settings. The date reads Today, Tomorrow, a weekday within the week, or the date itself, and turns the accent color once it is overdue. Ticking a repeating line moves it to its next date instead of checking it. When a line comes due, everyone on the note, or the person it is assigned to, gets an alert at its time, or at 9:00 when it has none, in each device's own time zone. A repeating line alerts on each of its days until someone ticks it, so a missed day doesn't silence the next. The alert's Done ticks the line, Snooze 1 hour moves it to an hour later, and a tap opens the note at the line. Settings says whether alerts are on for the device, and turns them off there and back on, as for a browser on a computer whose desktop app alerts too. The desktop app shows alerts whenever it runs, with its window open or closed, and a click on one opens the note at the line. It also connects Google Calendar, which puts a Niche Notes calendar in the person's own Google account. That calendar shows every dated task they can open, a minute after each change, and each event links to its line in the note. Changes go one way, so edits happen in Niche Notes.
- **Assigned tasks.** On a note shared with someone by name, a task can be assigned to its owner or anyone it is shared with. Assign, beside the date button, picks one or Nobody in a box like the date's, and a tap on the first name at the end of the line opens it too. Typing @ and a name on a line offers the people on the note, and picking one assigns the line to them and takes the words out of the text. Escape keeps them as words. A task assigned to someone is theirs alone: only they get its alert, count it and see it in Due and the Due widget, and find it in their Google Calendar. Whoever is assigned a task gets an alert on every device where they turned on alerts, saying who assigned which task in which note, and a tap opens the note at the line. Assigning yourself sends nothing. A task whose person is taken off the note is everyone's again. A guest sees a task's person only when it is the owner, and can't assign.
- **Due.** A calendar button beside the search box counts the unchecked tasks due today or earlier that aren't assigned to someone else, in every note outside the trash. It is there while any line has a date. A tap lists the dated tasks in place of the tree, in Past due, Today, Tomorrow and Later sections, under their notes, the note with the oldest line first, each with its date, in the accent color once it is overdue. Each section folds, and stays folded for that person on every device. A tap on a line opens its note with the cursor at the end of that line. A tap on a line's box ticks it without opening its note, and once the ticking has stopped for two seconds the ticked lines leave, or a repeating one moves to its next date. A past due task ends with Today and Tomorrow, which move it there without opening its note, and Move all to today beside Past due moves them all. A moved task keeps its time and repeat, as in the date box. It works offline, and for notes that were never opened on the device.
- **Private by default.** A note is visible only to its owner until the owner shares it with a specific person. Sharing grants full edit access to that note only, not to its children. The person it is shared with gets a notification saying who shared which note, on every device where they turned on alerts, and a tap opens it. The owner can also share links that let anyone edit or only read the note without an account: whoever opens one gets the note under a made-up name like Teal Otter. The share box lists each link with the day it was made and who came by it when, and turning one off takes the note away from its guests alone. Someone who opened both kinds can edit. A guest sees the note and nothing else: no tree and no notes of their own, nobody's name but its owner's, and a header that shows only the title, which they can't change. A guest who can only read gets no toolbar either. Live edits and cursors reach them all the same. Share is an outline of two people on a private note, and filled with the number of people once it is shared, so a shared note in the tree wears the filled icon too, like a pinned note's pin.
- **Your tree is yours.** Sharing a note does not move it. It appears at the top of the other person's tree, under their pins, and they drag it wherever they like. A note someone else owns shows their first name wherever it is listed. Its header has the filled people icon and the owner's first name where the owner has Share. Leave note in place of Delete note moves it to their own trash, where Restore brings it back and Leave for good drops the share for them alone. The owner's note is never touched.
- **Offline first.** Everything except sharing and History works without a connection: create, edit, move and delete, including notes shared with you. Changes merge when the connection returns. History needs one, since a note's versions from other devices live only on the server. A crossed-out cloud in the header says when the server can't be reached.
- **Real time.** Two people editing one note see each other's keystrokes and cursors. A cursor shows with its person's first name, or a guest's whole made-up name, while that person moves it, and goes after five seconds of stillness.
- **Trash, not confirmations.** Delete note is one tap in the note's menu. A note with notes under it asks first, on Delete note or Leave note, whether they go too. Alone, they move up to its parent. With it, they go to the trash as one entry, which Restore and Delete forever act on whole. The note goes to a Trash section at the bottom of the tree, where it can be read but not edited, restored, or deleted forever. A note restored while the note above it is still in the trash comes back at the top. Anything in the trash for thirty days is deleted for good, by the client the next time it starts and catches up with the server, so no server job is involved.
- **History.** History in a note's menu shows the note as it was at each minute of the last 20 minutes, each 10 minutes of the day, each hour of the day before and each day of the last two weeks, the newest first, with every device's and every person's edits. The chosen version shows read-only, scrolled to where this device last left the cursor, or to its end when that text came later. Going back to a version while History is open returns to where it was scrolled. Restore puts back its title and text as one edit, which syncs like any other and is a version too. Someone who can only read gets no History, and neither does a note in the trash.
- **Settings.** Light, dark or follow-the-device appearance, a Default or Confetti color scheme, a theme of fourteen colors under Default, and a compact, default or large density. The theme's color fills the note header and the selected row and tints the page and the tree, and it stays readable in light and dark. All but density follow the user to every device, and density stays with each device, since a phone and a desktop want different sizes. Settings ends with the server's build and, in the Android or desktop app, the app's, both numbered by commit count, so an update is easy to spot. Sign out sits in Settings under the person's name. In browsers and the desktop apps, Advanced has Export note, which picks a note in the tree and downloads it as Markdown, and Export all notes, which downloads a zip whose folders follow the tree, without the trash. The desktop apps save the file to Downloads under a name not taken there and say so in an alert. Tasks keep their boxes and nesting, and a dated task ends in its date, time, repeat and person the way Obsidian's Tasks plugin writes them.
- **Note colors.** Color in a note's menu picks its color, and that note then wears it under either scheme. Under Confetti a note without one gets a color from its id, and the whole app wears the open note's color. With no note open it wears the last note opened on that device, or the top note. Colors are each person's own, so on a shared note each person sees their own. A note with a color shows it as a stripe beside its grip in the tree, moving in with its nesting.
- **Note header.** The title, the crossed-out cloud when offline, Share or the owner's name, and dots that open the note's menu, on a phone and a desktop alike. The menu names each action beside its icon: Color, Pin, History, what checked tasks do, Uncheck all, Delete checked, and Delete note or Leave note, which asks whether the notes under it go too and says how many.
- **Widgets.** On Android, three kinds of home-screen widget, any number of each, 2×3 when added. A note widget shows a whole note you pick, read-only, with headings in bold and blank lines kept, under a header in the color the note wears for you. Adding or reconfiguring one opens the tree to pick from, and tapping it opens the note in the app. An All notes widget shows your tree as you folded it, and a tap on a note there opens it. Adding one opens the app just long enough to hand it your tree. A Due widget lists the dated tasks the way Due does, in its sections under their notes, each with its date under it. It has nothing to pick, so adding one opens nothing, and signing out empties it. A tap on a line's box there ticks it without opening the app, and once the ticking has stopped for two seconds the ticked lines leave, or a repeating one moves to its next date. Offline, the box opens the note at that line instead. A tap on its text opens the note at that line, and a tap on a section folds it, in the app too. Widgets refresh when you leave the app, within a minute of a change to one of your notes made anywhere else, every 30 minutes, and from a refresh button.
- **Native.** An Android app, a desktop app for macOS and Windows, and the web app, which Chrome and Edge install as an app too, all loading the same build from the server. Both apps sign in through the default browser, where the passkey works. The Android app updates itself from the project's releases: it downloads a newer one in the background and offers it in a quiet notification whose tap installs it. A dismissed offer comes back a day later, and a newer release is offered at once. Closing its window leaves it in the tray, where a click opens the window or closes it again and the right-click menu quits it. It starts at login, and it updates itself while its window is closed. A note's link from another app, such as a calendar event, opens in the default browser, which passes it on to the desktop app after asking once, and the note stays open in the tab too. Quick capture starts a new note from anywhere, with the cursor in its title. On a Mac ⌥⌘N does it and on Windows Ctrl+Alt+N, even with the window closed. On Linux the launcher's New note action does it, under whatever key the desktop's settings give it. On Android a long press on the app's icon and a Quick Settings tile both offer New note, which opens with the keyboard up. While that note is still blank, doing it again opens the same note instead of another.
- **Self-hosted.** One Docker container and one SQLite file. Login through Pocket ID passkeys, and a session lasts a year past the last launch. Sign out takes the notes off the device, and the next login asks which account to use instead of signing the same person back in. A person can be shared with once they have logged in. A backup of the file restores by putting it in place and starting the app, or runs as an offline copy to look at, and after a restore each device sends back whatever the backup lacked.

## Not in v1

Sharing a note with its children, images and attachments, iOS, view-only sharing.
